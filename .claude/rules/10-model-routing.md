# 10 — 서브에이전트 모델 차등 적용 (필수)

작업 성격에 따라 서브에이전트 모델을 **반드시 구분**해서 지정한다(HANDOFF §7.1의 사용자 지정과 같다).

| 작업 성격 | 모델 | 지정 방법 |
| --- | --- | --- |
| **분석 / 설계 / 리뷰** — 아키텍처 결정, 요구사항 분석, 코드리뷰, 계획 수립, 트레이드오프 판단 | **오케스트레이터와 동일 모델** | `model` 파라미터 **생략**(상속). 서브에이전트 정의에 모델이 고정돼 있으면 오케스트레이터 모델을 명시. `subagent_type: "fork"`는 항상 부모 모델을 상속한다. |
| **구현** — 도메인 로직, 스캐너·아카이브 리더, HTTP 핸들러, 화면, 테스트 작성, 리뷰 지적 수정 | `opus` | `model: "opus"` |
| **스크립트 실행 / 판단 없는 소규모 작업** — 빌드·테스트·게이트 실행, 출력 수집, 포맷팅, 파일 이동, 단순 치환 | `haiku` | `model: "haiku"` |

## 판단 규칙

- **애매하면 한 단계 위로.** 잘못된 설계 판단을 되돌리는 비용 > 상위 모델 호출 비용.
- 단, "실행만 하는 일"에 상위 모델을 쓰지 않는다. 판단이 없는 일은 haiku가 정답이다.
- 한 작업에 분석과 실행이 섞여 있으면 **쪼개서** 각각 맞는 모델에 준다.

## 예외: 코드 변경에 대한 리뷰

위 표의 리뷰 항목은 **codex를 쓸 수 없을 때의 폴백 모델**을 지정하는 것이다. codex를 쓸 수 있으면
리뷰 서브에이전트를 띄우지 않고 codex로 대체한다(택일).
**규범 원본은 `20-review-cycle.md`의 "2. 리뷰"**이며, 조건·예외·부분 실패 처리는 여기서 다시 서술하지 않는다.

적대적 검증(adversarial verify)은 리뷰가 아니라 판정이므로 위 표의 분석/설계 등급을 그대로 쓴다.
그 경계는 `30-workflow.md`가 규범 원본이다.
