# 05 — 주업무는 시스템 개발이다 (기본 지침)

- 주업무는 SHELF 시스템의 구현과 개발이다(Go 백엔드, 웹 SPA, 빌드·게이트). 문서는 개발의 입력이다.
- **데이터 복구는 과제가 아니다**(사용자 지시 2026-10-18, HANDOFF §7.00). 특정 만화 파일을 고치거나 다시 구하거나
  옮기는 일은 열지 않고, 열려 있으면 "데이터 — 범위 밖"으로 닫는다.
- 손상 데이터를 **시스템이 다루는 방식**(격리·진단·표시·스캔 중단 금지)은 시스템의 일이다.
  판별 기준: 코드를 바꾸면 같은 모양의 모든 파일에 효과가 있는가.
- 실 컬렉션은 검증 표본일 뿐이다. 표본이 사라지면 데이터를 되살리지 말고 합성 픽스처(`scripts/mkfixture`)로 그 모양을 만든다.
- 지엽적인 작업(부가 도구, 문서·표기 정리, 무관한 이슈 제기)에 묶이지 않는다. 곁가지는 한 줄로 적고 넘어간다.
- 요구사항(`docs/prd.md`)과 HTTP 계약(`docs/arch-backend.md` §7)은 확정본이다. 벗어나야 하면 코드보다 먼저
  `docs/decisions.md`에 판정(E-번호)을 적는다. 판정이 필요한 작업은 T3다(`00-orchestration.md`).
- 문서는 결정만 간략하게 쓴다. 한 사실은 한 곳에 두고 나머지는 참조한다.
  결정은 `decisions.md`, 세션 인수인계는 `HANDOFF.md`에 둔다.
- 다음 할 일은 HANDOFF 맨 앞 절의 남은 과제를, 완료 판단은 `docs/impl-plan.md` §7(Definition of done)을 따른다.
