# 문서 분할·색인

목차: 1. 읽기 · 2. 나누는 기준 · 3. 구조(분할 폴더) · 4. index.md · 5. 주제 문서 · 6. 분할 절차 · 7. 옛 경로 연속성 · 8. 검증

목적: 에이전트가 문서 묶음 전체가 아니라 지금 작업에 필요한 주제 문서만 읽게 한다. 프로젝트 지침이 위치·예외를 따로 정하면 그것을 따른다.

## 1. 읽기: index.md 먼저

그대로 따른다:

```
문서 찾기:
- [ ] 작업에 필요한 문서 폴더의 index.md를 먼저 읽는다
- [ ] 목차 표의 "언제 읽는가"가 지금 작업에 맞는 주제 문서만 연다. 나머지는 열지 않는다
- [ ] 주제 문서 안의 상대 링크는 지금 작업에 그 내용이 필요할 때만 따라간다
- [ ] 옛 경로 안내 문서(첫 줄 `<!-- moved-to: ... -->`)를 만나면 대응표에서 필요한 새 문서로 바로 간다
```

- index.md가 없거나 목차와 실제 파일이 다르면(8절 링크 검사로 확인) `ls`로 찾아 읽고, 그 사실을 보고 대상(단일 세션이면 사용자)에게 알린다. 그 폴더를 고칠 권한이 있으면 같은 작업에서 index.md를 맞춘다.

## 2. 나누는 기준

- 나눈다: 한 문서가 따로 읽히는 주제를 둘 이상 담고, 작업마다 필요한 주제가 다르며, 문서가 200줄을 넘는다. 사용자가 요청하면 줄 수와 관계없이 나눈다.
- 나누지 않는다: 주제가 하나다, 또는 두 부분이 늘 함께 읽혀야 이해된다.
- 주제 단위: 질문 하나에 답하는 단위(예: 목표·범위, 기능 하나, 데이터 계약, 운영 절차). 여러 주제에 걸친 문단은 소속 주제를 하나로 정하고 다른 주제 문서에서는 링크한다.

## 3. 구조: 분할 폴더

`<경로>/<문서>.md`를 나누면 index.md와 주제 문서를 담을 분할 폴더를 정한다. 프로젝트 지침이 위치를 정했으면 그것을 따른다.

- 기본(같은 이름 폴더): 다른 문서와 폴더를 같이 쓸 때.

  ```
  <경로>/<문서>.md            → 옛 경로 안내 문서(7절)
  <경로>/<문서>/index.md      → 초록·목차(4절)
  <경로>/<문서>/<주제>.md     → 주제 문서(5절)
  ```

- 선택(폴더 자체): `<경로>/`에 그 문서 하나뿐이거나 그 문서 전용 폴더면, 그 폴더가 곧 분할 폴더다.

  ```
  <경로>/<문서>.md            → 옛 경로 안내 문서(7절, moved-to: index.md)
  <경로>/index.md             → 초록·목차(4절)
  <경로>/<주제>.md            → 주제 문서(5절)
  ```

- 상위 폴더에 index.md가 있으면 그 목차에 분할 폴더의 `index.md`를 한 행으로 건다. 옛 안내 문서는 목차에 넣지 않는다.
- 주제 문서 파일 이름: 소문자·숫자·하이픈 주제 이름(예: `data-contract.md`). 읽는 순서가 중요하면 두 자리 번호를 앞에 붙인다(예: `01-goals.md`).

## 4. index.md 형식

폴더마다 하나 둔다. 맨 위에 제목과 초록(이 문서 묶음이 무엇인지, 어떤 작업에 쓰는지 몇 줄), 이어서 목차 표 하나만 둔다.

```
# <묶음 제목>

<초록: 이 묶음이 무엇이고 어떤 작업에 쓰는지 2~5줄>

| 문서 | 다루는 주제 | 언제 읽는가 |
| --- | --- | --- |
| [<주제 문서 제목>](<주제>.md) | <한 줄> | <이 문서가 필요한 작업·상황> |
```

- "언제 읽는가"는 작업·상황으로 쓴다(예: "결제 연동을 바꾸기 전", "F3 구현·테스트 작성 전"). "참고용"처럼 고를 기준이 없는 말은 쓰지 않는다.
- index.md에는 주제 문서의 내용을 옮겨 적지 않는다.
- 같은 폴더의 주제 문서는 모두 목차에 있어야 한다(8절 검사가 확인한다).

## 5. 주제 문서

- 주제 하나만 다루고 단독으로 읽혀야 한다. 맨 위에 제목과 목적 한두 줄을 둔다. 이해에 필요한 용어는 그 문서에서 정의하거나 정의한 문서로 링크한다.
- 다른 주제는 상대 링크(`[제목](other.md#앵커)`)로 참조하고 내용을 복사하지 않는다. 한 사실은 한 곳에만 둔다.
- 주제 문서를 추가·삭제·이름 변경하거나 다루는 주제가 바뀌면 같은 변경에서 index.md 목차와 그 문서를 가리키는 링크를 맞춘다.

## 6. 분할 절차

```
분할 진행:
- [ ] 1. 원문의 주제 목록과 각 주제의 범위(제목 단위)를 정했다
- [ ] 2. 분할 폴더(3절)에 주제 문서를 만들고 원문 문장을 그대로 옮겼다
- [ ] 3. 옮긴 문장 안의 상대 링크를 새 위치 기준으로 고쳤다(같은 이름 폴더면 한 단계 깊어지므로 원래 같은 폴더 문서는 `../`)
- [ ] 4. index.md를 만들고, 상위 폴더 index.md가 있으면 그 목차를 고쳤다
- [ ] 5. 옛 파일을 안내 문서로 바꿨다(7절)
- [ ] 6. 고칠 수 있는 교차 참조를 새 경로·앵커로 바꿨다(7절)
- [ ] 7. 검증(8절)을 통과했다
```

- 분할 중에는 내용을 고치지 않는다. 허용하는 변경은 제목 수준 조정, 주제 문서 맨 위의 제목·목적 줄, 중복을 링크로 바꾸기, 상대 경로 조정뿐이다. 내용 수정이 필요하면 따로 적어 두고 분할을 마친 뒤 별도 변경으로 한다.

## 7. 옛 경로 연속성

옛 파일 경로는 수정할 수 없는 기록(새 파일로만 추가하는 로그·결정 기록), 외부 문서, 커밋 메시지에 남아 있을 수 있다. 그래서 옛 파일은 지우지 않고 대응표만 담은 안내 문서로 남긴다.

```
<!-- moved-to: <문서>/index.md -->
# <원래 제목> (이동됨)

이 문서는 주제별 문서로 나뉘었다. [index.md](<문서>/index.md)에서 필요한 문서를 고른다.

| 옛 절 | 새 문서 |
| --- | --- |
| <a id="<옛 앵커>"></a><옛 제목> | [<새 문서>](<문서>/<주제>.md#<앵커>) |
```

- 위 예시는 같은 이름 폴더 기준이다. 폴더 자체를 분할 폴더로 쓰면 경로의 `<문서>/`를 뺀다.
- 첫 줄 `<!-- moved-to: ... -->`는 그대로 쓴다. 8절 검사가 이 표식으로 안내 문서를 알아보고 이동 대상이 있는지 본다.
- 대응표에는 원문의 모든 제목(`##` 이상)을 한 행씩 넣고, 행 앞에 옛 앵커를 `<a id="<옛 앵커>"></a>`로 남긴다. 수정할 수 없는 기록의 `<문서>.md#<옛 앵커>` 링크가 그 행에 닿고, 8절 검사도 통과한다. 옛 앵커는 8절 검사기와 같은 GitHub 방식으로 만든다(분할 전 원문을 `<a id>` 없이 검사기에 넣어 보면 확인된다).
- 고칠 수 있는 교차 참조는 새 경로·앵커로 바꾼다. 찾기: `grep -rn '<문서>.md' <저장소 루트> --include='*.md'`. 저장소의 지침 파일(AGENTS.md 등)에 있는 참조도 포함한다. 그 파일을 고칠 권한이 없으면 고칠 목록을 보고한다.
- 수정할 수 없는 기록 속 옛 링크는 고치지 않는다. 안내 문서가 그 링크를 받는다.
- 안내 문서는 사용자 승인 없이 지우지 않는다.

## 8. 검증

분할·색인 변경을 마치면 셋 다 실행하고 결과를 보고에 넣는다.

1. **본문 무손실**: 아래 첫 명령은 원문에만 있는 줄(누락 후보), 둘째 명령은 새 문서에만 있는 줄(추가분)을 보여 준다. 두 출력 모두 6절의 허용 변경이어야 한다. 아니면 되살리거나 뺀다. 줄 단위 비교라 절 사이에 문장을 옮긴 것은 잡지 못하므로 대응표와 주제 범위를 함께 본다.

   ```bash
   comm -23 <(git show <분할 전 커밋>:<경로>/<문서>.md | grep -v '^[[:space:]]*$' | sort -u) \
            <(cat <분할 폴더>/*.md | grep -v '^[[:space:]]*$' | sort -u)
   comm -13 <(git show <분할 전 커밋>:<경로>/<문서>.md | grep -v '^[[:space:]]*$' | sort -u) \
            <(cat <분할 폴더>/*.md | grep -v '^[[:space:]]*$' | sort -u)
   ```

   폴더 자체를 분할 폴더로 쓰면 `<분할 폴더>/*.md`에서 옛 안내 문서를 뺀다.

   git 밖이면 `git show ...` 대신 분할 전 사본을 쓴다.

2. **링크·앵커·색인**: 그대로 실행한다. 종료 코드 0이어야 한다.

   ```bash
   python3 .agents/skills/writing-project-docs/scripts/check_md_links.py <문서 루트>
   ```

   `<문서 루트>`는 분할 폴더·옛 안내 문서·상위 index.md·옛 경로를 가리키는 기록을 모두 포함하는 폴더다(보통 저장소의 `docs`).

   검사 항목: 상대 링크의 대상 파일, `#앵커`(GitHub 제목 앵커·`<a id>`), index.md 목차에 빠진 같은 폴더 문서·하위 문서 묶음, 안내 문서의 moved-to 대상. 숨김 폴더는 건너뛴다. 스크립트를 고치면 `python3 -m unittest discover -s .agents/skills/writing-project-docs/scripts -p 'test_*.py'`로 테스트한다.

3. **옛 경로 잔여**: `grep -rn '<문서>.md' <저장소 루트> --include='*.md'` 결과가 안내 문서 자신과 수정할 수 없는 기록뿐이어야 한다.
