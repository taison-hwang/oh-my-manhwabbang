# 구현: TDD

테스트가 실행 가능한 명세다. 구현 상세의 진실은 최신의 검증된 코드와 테스트이고, 코드의 동작·분기·자료구조를 문서에 옮기지 않는다.

명령은 프로젝트가 정한다: 테스트·전체 검사는 `AGENTS.md`의 "검사 명령", 뮤테이션은 "뮤테이션". 이 스킬은 도구를 정하지 않는다.

## TDD 대상

- 대상: 도메인 규칙, 서버·API, 변환·오류 처리, 데이터 검증, 렌더링·내보내기, 화면 상태·상호작용.
- 제외: 설정, 골격, 문서, 기계적 생성 코드. 제외 대상은 위험에 비례해 검증한다.

## 절차

테스트 하나 단위로 반복한다.

```
TDD 진행:
- [ ] 1. 요구사항·외부 계약에서 기대값을 정했다
- [ ] 2. 실패하는 테스트를 작성·실행해 실패를 확인했다
- [ ] 3. 그 테스트를 통과시키는 최소 구현을 했다
- [ ] 4. 관련 테스트가 통과한다
- [ ] 5. 리팩터링 후 관련 테스트와 바뀐 파일의 lint·타입 검사가 다시 통과한다
- [ ] 6. [완료] 보고 전에 "뮤테이션 확인"을 처리했다
```

- 편집 직후 빠른 검사는 hook이, 전체 검사는 [완료] 보고 때 `herdr-report` 관문이 돌린다. role이 없는 단일 세션은 끝내기 전에 `.agents/bin/herdr-check`를 직접 돌린다.
- 관련 테스트(4·5단계)는 프로젝트 hook이 맡지 않으면 검사 명령으로 직접 돌린다. 매 실패·통과 사이클마다 전체 검사를 돌리지 않는다.
- 일부러 실패 상태로 턴을 끝낼 때(실패 테스트만 쓰는 단계를 맡은 경우)는 보고에 그 사실과 실패 내용을 적는다.
- 검사 실패는 고친 뒤 진행한다. lint 규칙을 끄거나 무시 주석을 달 때는 그 자리에 이유를 남긴다. hook이나 관문을 건너뛰지 않는다.

## 뮤테이션 확인

- `AGENTS.md`에 뮤테이션 명령이 없으면 하지 않고 보고에 "뮤테이션 미설정"을 적는다.
- 분기·경계 조건이나 도메인·상태 로직을 바꿨으면 [완료] 보고 전에 실행한다. 그 밖에는 생략하고 보고에 "뮤테이션 생략(분기 변경 없음)"을 적는다. 프로젝트가 범위를 정했으면 그것을 따른다.
- 점수 임계값으로 막지 않는다. 생존 변이마다 판단한다: 동작이 실제로 달라지는 변이(경계값·분기)면 그 경우를 드러내는 테스트를 추가하고, 동등 변이나 의미 없는 문구 변이는 넘긴다.
- 보고에 변이 생성·잡힘·생존 수와 처리한 생존 변이를 적는다.

## 테스트 작성 규칙

- 구현을 돌려 나온 값을 기대값으로 옮겨 적지 않는다.
- 버그 수정은 그 버그를 재현하는 실패 테스트부터 쓴다.
- 실패 경로·입력 검증·오류·경계·회귀 위험을 테스트한다. 테스트가 불가능하면 이유와 대체 검증을 남긴다.
- 테스트 이름은 검증하는 규칙을 문장으로 드러낸다.
- 완료 보고에는 먼저 쓴 테스트, 구현 전 실패 결과, 최종 테스트 결과를 넣는다.
