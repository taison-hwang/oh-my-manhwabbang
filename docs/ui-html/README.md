# 디자인 프로토타입 사본 — 무엇이 최신인지

이 디렉터리는 **읽기 전용 참조**다. 제품이 아니라 제품이 따라가는 원본이고,
정본은 사용자의 Claude Design 프로젝트 *다기능 도서관 뷰어 프로토타입*
(`ad00fd5c-77e7-44fa-847d-56c9071fa334`)이다. 여기 있는 것은 그때그때 받아 둔 **사본**이다.

| 파일 | 받은 날 | 상태 |
|---|---|---|
| `만화방 v2 soft.dc.html` | **2026-08-09** | **최신.** soft-UI 스킨, 루트 폴더 피커, 맞춤 네 종(화면 포함) |
| `다기능 도서관 뷰어 프로토타입.zip` | 2026-07-28 | **낡음.** E-27 이전 판이다 — 아래를 읽을 것 |

## 낡은 사본은 조용히 틀린 답을 준다 — 실제로 두 번 그랬다

15세션차(2026-08-09)에 서로 독립적인 두 에이전트가 zip 안의 2026-07-28 판을 읽고
**맞춤 `화면`은 넷째**라고 결론지었다. 그것은 그 날짜에는 맞는 말이었다. 그 사이

1. **E-27**(5세션차)이 프로토타입에서 `화면`이 사라진 것을 보고 옵션을 지웠고,
2. 사용자가 2026-08-09에 그것을 **되살리면서 자리도 셋째로 옮겼다**(**E-44**).

즉 zip은 **두 번 낡았다** — 옵션이 없던 것으로 한 번, 자리로 또 한 번. 그런데 두 에이전트 모두
자기가 읽은 것이 최신인지 확인할 방법이 없었다. `docs/ui-shots/`의 캡처와 `docs/design.md`도
같은 시점에 묶여 있어 **세 출처가 사이좋게 같은 낡은 답**을 냈고, 그래서 교차 확인이 통하지 않았다.

**그러므로 규칙 하나.** 프로토타입을 근거로 무언가를 주장하기 전에 **받은 날짜를 위 표에서 확인하고**,
그 날짜 이후에 열린 판정이 `docs/decisions.md`에 있는지 볼 것. 판정과 사본이 어긋나면
**판정이 이긴다**(HANDOFF §3). 사본은 증거가 아니라 그 날의 스냅숏이다.

## 사본을 새로 받는 법

`DesignSync`는 **오케스트레이터 전용이다** — 서브에이전트에 위임하면 "도구 없음"으로 돌아온다
(9세션차와 15세션차가 같은 벽에 부딪혔다). 오케스트레이터가 직접:

```
DesignSync get_file  projectId=ad00fd5c-77e7-44fa-847d-56c9071fa334
                     path="만화방 v2 soft.dc.html"
```

받은 뒤 이 표에 날짜를 갱신할 것. 갱신하지 않은 사본은 다음 세션에 위와 같은 방식으로 비용을 청구한다.
