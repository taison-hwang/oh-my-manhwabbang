## 무엇이 바뀌었나

- 새 진입점 `scripts/deploy/library/books.sh` — `check`·`status`·`init`·`start`·`stop`·`restart`·`tunnel apply`·`tunnel restart`·`rollback`·`verify`. 단계별 영향(sudo 여부, 끊기는 서비스)과 종료 코드는 `books.sh --help`가 정본이다. 안전 검사는 기존 `preflight.sh`, ingress 변경은 `tunnel-apply.sh`·`tunnel-rollback.sh`, 노출 검사는 `verify-public.sh`를 그대로 부른다.
- `books_proc.py` — `/proc`·`ss`로 "이 포트의 주인", "이 pid가 `--bin --config`을 돌리는가", "data_dir의 파일을 연 프로세스"를 읽는다(쓰기 없음).
- `preflight.sh --own-pid PID` — 실행 중인 인스턴스가 포트를 쥔 경우(`restart`·`tunnel apply`) P13을 통과시킨다. 그 밖의 검사는 그대로다.
- 자동 테스트 `scripts/deploy/library/tests/test_books.py`(가짜 shelf·cloudflared·systemctl·sudo), `make test`에 들어갔다.

## 안전 장치 (스크립트가 강제하는 것)

| 조건 | 동작 |
| --- | --- |
| `auth.mode`≠oidc, `listen` 비루프백, issuer·client_id·audience·redirect_url이 books 등록값과 다름, `trusted_proxy_headers` 켬, password 동시 설정 | `start`·`restart`·`tunnel apply`·`check`가 preflight FAIL로 **아무것도 바꾸지 않고 종료 3** |
| 같은 data_dir의 파일을 연 프로세스(옛 `:9909` shelf 등)가 있음 | `start` 거부(종료 4), 그 pid와 명령줄 출력 |
| `start` 직전 | data_dir 전체를 `<data_dir>.bak-<UTC>`로 복사(아래 "백업 범위"). 백업·데이터는 지우지 않는다 |
| 기동 뒤 헬스(`/api/health` 200, `--wait` 초) 또는 로컬 verify FAIL | 새 인스턴스를 TERM, pidfile 삭제, 로그 위치·백업·직전 정상 설정 경로 출력(종료 5) |
| `restart` | 새 설정의 preflight를 먼저 하고 실패하면 **기존 프로세스를 멈추지 않는다**(종료 3) |
| `stop` | pidfile의 pid가 살아 있고, 그 pid의 명령줄이 `--bin`·`--config`과 일치하고, 설정의 포트 주인이 그 pid일 때만 TERM. 하나라도 다르면 종료 6. 15초 안에 안 끝나도 KILL하지 않는다 |
| `tunnel apply` | 실행 중 인스턴스의 로컬 verify가 FAIL 0일 때만 `sudo tunnel-apply.sh`(백업·검증·실패 시 복원). cloudflared는 재시작하지 않는다 |
| `tunnel restart` | `sudo systemctl restart cloudflared` → 활성 확인 → 공개 verify. 하나라도 실패하면 `tunnel apply`가 기록한 백업으로 되돌리고 다시 재시작(종료 8) |
| 확인 | 변경 단계는 대화형 `yes` 또는 `--yes`. sudo 단계는 대화형 `sudo` 또는 `--yes-sudo`로 **따로** 확인(`--yes`로는 안 된다). 확인이 없으면 종료 10 |
| `--dry-run` | 읽기 검사만 하고 바꿀 일을 `>> would:`로 출력 |
| 설정 파일 | 쓰지 않는다. `init`만 새 파일을 만들고, 대상이 있으면 거부(종료 9) |

**백업 범위.** data_dir 전체(`index.db`·`user.db`·`auth.db`·`session.key`와 `-wal`·`-shm`)를 복사한다. [실행] 지금 운영 data_dir `resources/shelf`는 169,783,296 B(대부분 `index.db` 168,669,184 B), 그 파일 시스템의 여유는 약 1.69 TB다. 그래서 범위를 줄이지 않고 통째로 뜬다. 여유가 크기의 2배보다 작으면 `start`가 아무것도 바꾸지 않고 멈춘다. cache_dir(썸네일 캐시)은 다시 만들 수 있어 백업하지 않는다. 백업은 지우지 않으므로 쌓인다 — 정리는 사용자가 한다.

## 사용 절차 (§5 A~F 대체)

```bash
cd /mnt/data/codejobs/projects/betterax-proto/zip-viewer
B=scripts/deploy/library/books.sh          # 기본값: --config ./shelf.books.yaml --bin ./dist/shelf --workdir .
```

1. **설정 만들기(한 번)** — `$B init --from shelf.yaml`. `shelf.yaml`을 읽어 `server`를 `127.0.0.1:9910`으로, `auth` oidc 블록(books 값)을 넣은 **새** `shelf.books.yaml`을 쓴다. 원본의 주석은 옮기지 않는다. `server.allow_root_editing`은 원본 값(지금 `true`)을 유지하므로 공개 서버에서 끌지 직접 정한다. 기대: `>> wrote …/shelf.books.yaml`.
2. **점검** — `$B check`. 기대: preflight 표 `FAIL 0`, P6(allowed_subs 비어 있음) WARN, `>> check: no FAIL`. 옛 `:9909`가 `0.0.0.0`에서 돌고 있으면 P14가 FAIL인 것이 정상이다(3단계 뒤 다시 돌리면 FAIL 0).
3. **옛 `:9909` 서버 중지(사용자, 스크립트 밖)** — 그 서버는 `books.sh`가 띄운 것이 아니라서 `stop`이 끄지 않는다(명령줄·pidfile 불일치). 띄운 방식대로 멈춘다(`ss -ltnp | grep :9909`로 PID 확인 → `kill <PID>`). 멈추지 않으면 다음 단계가 종료 4로 거부한다.
4. **기동** — `$B start`(대화형 `yes`, 또는 `--yes`). 기대: `>> backup: …/resources/shelf.bak-<UTC>`, `>> started pid N`, verify 표 `FAIL 0`, `>> running: pid N on 127.0.0.1:9910`. 실패면 새 인스턴스는 이미 멈췄고, 출력의 "recovery:" 줄이 로그·백업·직전 정상 설정을 가리킨다.
5. **ingress 적용(sudo)** — `$B tunnel apply`(대화형 `sudo`, 또는 `--yes-sudo`). 기대: tunnel-apply 표 T1~T5 PASS, `>> ingress rule added (backup /etc/cloudflared/config.yml.bak-<UTC>)`. 아직 공개되지 않는다(재시작 전).
6. **cloudflared 재시작(sudo, 수 초 중단)** — 시간을 골라 `$B tunnel restart`. **같은 터널의 `auth.betterax.net`·`ohmyassets.betterax.net`이 몇 초 끊긴다**(stock·ssh는 다른 터널). 기대: 공개 verify 표 FAIL 0, `>> public: https://books.betterax.net passes verify`. 실패하면 스크립트가 백업으로 되돌리고 다시 재시작한다(종료 8).
7. **첫 로그인과 허용 목록** — 브라우저로 `https://books.betterax.net/` → `uni-auth로 로그인` → 첫 로그인은 403 화면이 정상, 화면의 `sub`를 복사한다. `shelf.books.yaml`의 `auth.oidc.allowed_subs`(필요하면 `admin_subs`·`legacy_owner_sub`)에 **직접** 넣고 `$B restart`. 스크립트는 설정을 고치지 않고 다시 띄우기만 한다. 브라우저 경로·쿠키 조건은 U-R3b 기록 §2·§5 F와 같다.

상태 보기는 언제든 `$B status`(읽기 전용: pidfile, 포트·헬스, shelf 프로세스, 9909/9910 리스너, ingress 규칙 유무, cloudflared 프로세스, DNS, 공개 URL 응답). 공개 중단은 `$B rollback`(기록된 백업으로 되돌리고 재시작, sudo), 서버 중지는 `$B stop`.

## 위험·열린 문제

- shelf 자체의 설정 검증(preflight가 보지 않는 키)은 기동해야 드러난다. `restart`에서 그런 오류가 나면 옛 프로세스는 이미 멈춘 뒤다 — 스크립트는 새 인스턴스를 멈추고 직전 정상 설정(`<state>/last-good.yaml`)으로 다시 띄우는 명령을 출력한다 [추론: 실제 바이너리로 이 경로를 돌려 보지 않았다].
- `books.sh`로 띄운 서버는 `nohup` 백그라운드 프로세스다. 기계를 재부팅하면 다시 `start`해야 한다(systemd 단위는 범위 밖).
- 로그아웃 복귀(Hydra `post_logout_redirect_uris` null)는 U-R3b 기록의 열린 문제 그대로.
