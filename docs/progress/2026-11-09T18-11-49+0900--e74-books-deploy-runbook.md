## 주소 변경으로 운영 쪽에서 따로 해야 하는 것

1. **uni-auth 클라이언트 `zip-viewer` 갱신** — `redirect_uris`·`post_logout_redirect_uris`·`audiences`·`client_uri`를 books 값으로. 게이트웨이 관리 API로 작업자가 한다(U-R3b, 승인 범위 1건). 갱신 전까지 새 설정(books 값)으로 띄운 서버의 로그인은 uni-auth가 `redirect_uri` 불일치로 거절한다 [추론].
2. **DNS `books` CNAME** — `cloudflared tunnel route dns gift4me-tunnel books.betterax.net`. 작업자가 한다(U-R3b, 승인 범위 1건). 옛 `library` 레코드가 있으면 지우지 않고 보고한다.
3. 아래 3·4·7·9단계(서버 중지·기동, `/etc` ingress, cloudflared 재시작, 허용 목록)는 **사용자가 직접** 한다. 지금 상태에 맞춘 정확한 명령 블록은 U-R3b 기록에 둔다.

- 배치 기준(E-74 §2.18): **oidc 단일 인스턴스, `127.0.0.1:9910` 바인드**.
- **지금 `*:9909`에서 shelf가 돌고 있다** [실행: 2026-11-09 18:1x `preflight.sh` P14 FAIL `*:9909`, P15 `dist/shelf` PID 3670868]. 와일드카드 리스너라 터널 전에 멈춰야 한다(3단계).
- 터널 적용(7단계)의 cloudflared 재시작은 같은 터널의 **`auth.betterax.net`·`ohmyassets.betterax.net`을 몇 초 끊는다** [추론, 실제 중단 시간 미확인].

## 0. 바이너리 빌드 (권한 불필요)

```bash
cd $REPO && git log --oneline -1          # U-R3a가 병합된 main인지 확인
make build && dist/shelf --version
```
기대: 에러 없이 끝나고 `--version`이 방금 커밋을 보인다.

## 1. 설정 만들기

```bash
cp $D/shelf.library.example.yaml $CFG
$EDITOR $CFG        # roots, data_dir, cache_dir의 <...>를 기존 서버 값으로 채운다
```
등록값(`issuer`·`client_id`·`audience`·`redirect_url`)은 바꾸지 않는다. 옛 런북으로 이미 만든 `$CFG`가 있으면 `audience`·`redirect_url`의 호스트를 `books.betterax.net`으로 고친다(2단계 P10·P11이 옛 값을 FAIL로 잡는다 [실행: 옛 호스트 사본으로 확인]). `allowed_subs`는 비워 둔다(9단계).

## 2. 점검 (권한 불필요, 읽기 전용)

```bash
$D/preflight.sh --config $CFG --bin $REPO/dist/shelf --port $PORT
```

기대: FAIL 0(3단계 전이면 P14만 FAIL). P6(allowed_subs 비어 있음)은 WARN이 정상. P10·P11이 `https://books.betterax.net/api`, `https://books.betterax.net/api/auth/oidc/callback`을 보인다.

## 3. 기존 서버 중지와 데이터 백업 (사용자 직접)

```bash
ss -ltnp | grep -E ':9909\b'               # 기존 서버의 PID 확인
kill <PID>
ss -ltnH 'sport = :9909' | wc -l           # 0
DATA=$(python3 -c "import yaml;print(yaml.safe_load(open('$CFG'))['storage']['data_dir'])")
cp -a "$DATA" "$DATA.bak-$(date -u +%Y%m%dT%H%M%SZ)"; ls -d "$DATA".bak-*
```
서버를 멈추기 전에 복사하지 않는다(WAL 불일치). 실패 시 기존 서버를 원래 방식으로 다시 띄우면 이전과 같다.

## 4. 새 서버 시작 (사용자 직접, 아직 터널 없음)

```bash
cd $REPO && nohup dist/shelf --config $CFG >> ~/shelf-library.log 2>&1 &
sleep 3; tail -20 ~/shelf-library.log; ss -ltnp | grep -E ":$PORT\b"
```
기대: `127.0.0.1:$PORT`만 listen, 로그에 오류 없음. 기동 실패(exit 2)면 로그 한 줄이 이유(E-74 §2.19 설정 검사).

기대: **FAIL 0**. 하나라도 FAIL이면 멈추고 보고한다. 6단계로 가지 않는다.

## 6. DNS (U-R3b에서 작업자가 함)

U-R3b가 `cloudflared tunnel route dns gift4me-tunnel books.betterax.net`을 실행하고 결과를 기록한다. 규칙이 없는 동안 `https://books.betterax.net/`은 catch-all **404**다. 사용자는 `curl -sI https://books.betterax.net/ | head -1`로 404만 확인한다. 되돌리기: 대시보드에서 `books` CNAME 삭제.

## 7. 터널 적용 — 중단 시점 (사용자 직접, sudo)

```bash
sudo $D/tunnel-apply.sh --service http://127.0.0.1:$PORT            # 파일만 바꾸고 표 확인
sudo systemctl restart cloudflared                                   # 시간을 골라. auth·ohmyassets 몇 초 끊김
```
(`--restart`를 붙이면 표가 모두 PASS일 때 한 번에 재시작한다.) 스크립트는 `/etc/cloudflared/config.yml`을 `.bak-<UTC>`로 백업하고, catch-all 앞에 books 규칙을 넣고, `ingress validate`와 규칙 확인 다섯 가지(T1 validate, T2 books → `:$PORT`, T3 auth → 8443, T4 ohmyassets → 18100, T5 그 밖 → 404)를 한다. 하나라도 틀리면 백업을 되돌리고 재시작하지 않는다.

[실행] `/etc/cloudflared/config.yml` 사본에 `tunnel-apply.sh --config-path`로 리허설: 표 PASS 5·FAIL 0, 삽입된 규칙은 `hostname: books.betterax.net`, `service: http://127.0.0.1:9910`, `httpHostHeader: books.betterax.net`. 재실행은 "already has a rule"로 거부, `tunnel-rollback.sh --config-path` 뒤 사본이 원본과 바이트 동일, `--config-path`와 `--restart`를 함께 주면 거부. 실제 `/etc/cloudflared/config.yml*`의 sha256은 전후 동일(`89bbb180…7842`).

재시작 뒤 확인:
```bash
journalctl -u cloudflared -n 30 --no-pager | grep -i 'registered tunnel connection'
curl -sI https://auth.betterax.net/.well-known/openid-configuration | head -1
curl -sI https://ohmyassets.betterax.net/ | head -1
```
실패·이상 시: `sudo $D/tunnel-rollback.sh --backup /etc/cloudflared/config.yml.bak-<UTC> --restart`(apply가 마지막 줄에 정확한 명령을 출력한다).

## 8. 공개 우회 경로 검증 (권한 불필요)

```bash
$D/verify-public.sh --public          # 기본 URL https://books.betterax.net
```
기대: FAIL 0. 하나라도 FAIL이면 즉시 7단계의 롤백을 하고 보고한다.

## 9. 실제 로그인과 허용 목록 (사용자 직접)

1. `https://books.betterax.net/` → 서버가 그린 로그인 화면 → `uni-auth로 로그인`.
2. 첫 로그인은 **403 화면**이 정상(허용 목록이 비어 있다). 화면의 `sub`를 복사한다.
3. 서버를 멈추고 `$CFG`에 `allowed_subs: ["<sub>"]`, `admin_subs: ["<sub>"]`, `legacy_owner_sub: "<sub>"`를 넣고 다시 시작한다.
4. 다시 로그인 → 서재와 이전 진행률이 보인다.

## 되돌리기

옛 런북의 표와 같다(주소만 `books`). 터널만 되돌림: `tunnel-rollback.sh --restart`. 공개를 멈추고 서버도 내림: 롤백 → `kill`. password 모드·인증 없음으로 돌아가려면 **먼저 터널을 되돌린다**(E-74 §2.18). 데이터를 이전 상태로: 서버 정지 → 백업 복원 → 옛 바이너리.
