# F-1 화살표 글리프를 벤더 서체로 — 원인, 고정, 픽셀 기준 갱신

## 결론

UI가 글자로 쓰는 `← ↑ → ↓`(L→R/R→L 라벨, 정렬 열의 ↑↓, 단축키 `← →`)는 모든 글꼴 스택에서 시스템 글꼴로 떨어졌다. e2e 픽셀 기준(step 11c)은 저장소 변화 없이 실패했다. 네 글자만 담은 벤더 face `Shelf Arrows`를 다섯 스택 앞쪽에 두어 고정했다. 기준은 82장 갱신했다(화살표 81장 + e45 4장, 아래 따로 적음).

## 원인 (실행 확인)

- e2e는 Playwright 번들이 아니라 `channel: 'chrome'`(시스템 Google Chrome 157.0.8103.38, 2026-11-08 16:30 dpkg 업그레이드)으로 돈다.
- 벤더 woff2의 cmap: 고운바탕·Noto Serif TC·Noto Sans JP에 화살표 0, Archivo는 ↑↓만 있다.
- 합성 픽스처 격리 서버에서 CDP `CSS.getPlatformFontsForNode`로 잼: 본문 스택의 화살표는 Liberation Serif(시스템), `<kbd>`의 `← →`는 Liberation Mono(시스템).
- 2026-11-09 P-71b 라운드에서 11c changed 84장. web 코드는 main(d0d669a, 905d02a와 web·internal·cmd·픽스처·기준 동일)과 같았다. 울프가이와 무관한 화살표 샷이 섞여 있어 main도 같은 이유로 빨갛다고 추론한다(main 라운드 직접 실행은 안 함).
- E-69(b3468ab) 기준의 화살표는 Noto Serif CJK 모양과 닮았고, E-69 이전 기준(b3468ab^)은 지금의 Liberation 모양이었다(썸네일 비교). 기록 당시 Chrome의 대체 선택이 달랐다고 추론한다. 그 환경은 미확인이다.

## 고정

- `scripts/mkfonts/subset.py --only arrows`: Noto Serif CJK TC에서 ←↑→↓만 잘라 `web/src/assets/fonts/shelf-arrows-400/700.woff2`(1 056 B / 1 020 B)를 만든다. fontTools 4.68(`uv run --no-project --with 'fonttools[woff]'`). 기존 CJK 파일은 4.68로 바이트 재현이 안 돼(`--check` DIFFERS) 다시 만들지 않았다.
- `fonts.css`: `'Shelf Arrows'` 400/700, `unicode-range: U+2190-2193`.
- `tokens.css`: heading·ui·ja·seal 스택에 시스템 글꼴보다 앞에 둔다. `<kbd>`용 `--font-mono`를 더하고, `tailwind.config.ts`의 `fontFamily.mono`가 이를 가리킨다.
- 바이너리 33 411 234 → 33 415 330 B(+4 096). 새 런타임 의존성 0, 시스템 글꼴 패키지 변경 없음.

## 검사

- `web/src/styles/fontCoverage.test.ts` "arrows (F-1)": 소스에 쓰인 화살표 × 다섯 스택 × 400/700을 `@font-face`(unicode-range)와 woff2 cmap에 조인한다. 시스템 글꼴이나 합성 굵기에 닿으면 실패한다. 뮤테이션 5건 RED: heading에서 제거, mono에서 제거, 700 face 누락, range 축소, 새 화살표 ⇄.
- `web/e2e/03-series-detail.spec.ts` "6.5 (F-1)": CDP로 목록 머리와 시리즈 화면의 화살표를 실제로 그린 글꼴이 웹폰트인지 단정한다(시스템 대조군 포함). heading에서 Shelf Arrows를 뺀 빌드로 RED를 확인했다.

## 픽셀 기준 갱신 (82장)

- 화살표 81장: F-1 라운드 렌더를 수정 전 렌더(P-71b 라운드)와 원본 해상도로 비교했다. 각 샷에서 바뀐 곳은 화살표 자리 1~3곳뿐이다(뷰어 L→R/R→L, 시리즈 상세 기본·L→R·R→L, 목록 머리 ↑/↓).
- **e45-viewer-stale-progress 4장(따로 밝힘)**: 화면에 화살표가 없다. F-1 이전·이후 렌더가 바이트 동일하고, 오늘 두 라운드에서 결정적이다. 기준과의 차이는 썸네일 해상도에서 안 보이는 잡음 수준이다(기준과 SHA가 같은 e27과 같은 수준). 원인은 미확인이다(3.4초 알림의 촬영 시점 차이로 추정). Orchestrator 결정 (A)로 함께 갱신했다(2026-11-09).
- manifest 해시 변경 82건 = 11c changed 82장과 일치. 썸네일 JPEG은 77개만 바뀌었다(나머지 5장은 축소 뒤 같음).
- `docs/ui-shots/built/` 리뷰 참조 세트는 갱신 전부터 기록된 촬영이 없다(item aj). 이번에 다시 찍지 않았다.
