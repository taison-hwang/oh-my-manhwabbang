# 사용자 요구사항 정의서 (URD)
## 아카이브 기반 만화/도서 웹 뷰어 시스템

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 |
| 작성일 | 2026-07-27 |
| 상태 | 초안 (Draft) |
| UI 방침 | 라이브러리 그리드 기반 하이브리드 (그리드/리스트 토글 + 이어보기 + 커맨드 팔레트) |
| 기술 방침 | Go 단일 바이너리 백엔드 + React/Vite/TS 프론트엔드 embed |

## 1. 문서 개요

### 1.1 목적
로컬 스토리지(대용량 볼륨)에 ZIP 압축 파일 또는 폴더 형태로 축적된 만화·도서 이미지 컬렉션을, **압축 해제 없이** 웹 브라우저에서 열람할 수 있는 시스템의 사용자 요구사항을 정의한다.

### 1.2 범위
- 다중 루트 디렉터리 스캔 및 시리즈 단위 카탈로그화
- ZIP 아카이브 내부 이미지의 직접 스트리밍 서빙
- 폴더 내 이미지 파일 서빙
- PDF 페이지의 서버 사이드 래스터화 서빙
- 웹 뷰어 UI (라이브러리 탐색 + 리더)
- 썸네일 캐시 및 읽기 진행률 관리

### 1.3 용어 정의

| 용어 | 정의 |
|---|---|
| **루트 (Root)** | 설정 파일에 등록된 스캔 대상 최상위 디렉터리. 복수 등록 가능 |
| **시리즈 (Series)** | 루트의 직계 자식 1개 항목(폴더 1개 또는 ZIP/PDF 파일 1개). 관리·표시의 기본 단위 |
| **권 (Book)** | 시리즈 내부의 열람 가능한 단위. ZIP 파일, 이미지가 담긴 하위 폴더, PDF 파일 중 하나 |
| **페이지 (Page)** | 권을 구성하는 단일 이미지. ZIP 엔트리, 파일, 또는 PDF 페이지에 대응 |
| **인덱스 (Index)** | 스캔 결과를 저장한 SQLite 캐시. 파일 시스템이 원본이며 언제든 재구축 가능 |
| **아카이브 (Archive)** | ZIP 등 컨테이너 파일의 총칭 |

### 1.4 참여자
- **주 사용자**: 컬렉션 소유자 본인 (단독 또는 소수 가족 구성원)
- **운영자**: 동일인. 별도의 운영 인력 없음
- **접속 환경**: 데스크톱 브라우저(주), 태블릿·모바일 브라우저(부)

## 2. 시스템 개요

### 2.1 데이터 계층 구조

```
루트 (config에 N개 등록)
 └─ 시리즈  = 루트의 직계 자식 1개
     └─ 권   = 시리즈 하위의 ZIP / 이미지 폴더 / PDF
         └─ 페이지 = ZIP 엔트리 / 이미지 파일 / PDF 페이지
```

### 2.2 시리즈-권 판별 규칙

| 루트 직계 자식의 형태 | 시리즈 | 권 구성 |
|---|---|---|
| 폴더 안에 ZIP 파일 다수 | 폴더 | ZIP 각각이 1권 |
| 폴더 안에 하위 폴더 다수, 각 하위 폴더에 이미지 | 폴더 | 하위 폴더 각각이 1권 |
| 폴더 안에 이미지 파일이 직접 존재 | 폴더 | 시리즈 자체가 단일 권 |
| ZIP 파일 1개 | 해당 ZIP | 자기 자신이 단일 권 |
| PDF 파일 1개 | 해당 PDF | 자기 자신이 단일 권 |
| 위 형태가 혼재 | 폴더 | 각 요소를 개별 권으로 병합 처리 |

### 2.3 시스템 구성

```
[브라우저]  ── HTTP/JSON + 이미지 스트림 ──  [Go 단일 바이너리]
                                                ├─ HTTP 서버 + 정적 자원(embed)
                                                ├─ 스캐너 / 인덱서
                                                ├─ ZIP 랜덤 액세스 리더
                                                ├─ PDF 래스터라이저
                                                ├─ 썸네일 워커
                                                ├─ SQLite 인덱스 (재구축 가능)
                                                └─ 썸네일 캐시 디렉터리
                                                        │
                                            [읽기 전용 미디어 볼륨 N개]
```

## 3. 기능 요구사항

### 3.1 루트 및 설정 (FR-CFG)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-CFG-001 | 시스템은 설정 파일(YAML)을 통해 복수의 루트 디렉터리를 등록할 수 있어야 한다. 각 루트는 고유 식별명(name)과 절대 경로(path)를 가진다 | 필수 |
| FR-CFG-002 | 루트별로 활성/비활성 상태를 지정할 수 있어야 한다 | 선택 |
| FR-CFG-003 | 설정 파일에서 캐시 디렉터리 경로, 서버 포트, 썸네일 크기, 동시 스캔 워커 수를 지정할 수 있어야 한다 | 필수 |
| FR-CFG-004 | 시리즈 식별자(series_id)는 `루트명 + 상대경로`의 해시로 생성되어, 루트의 물리 경로가 바뀌어도 읽기 진행률이 유지되어야 한다 | 필수 |
| FR-CFG-005 | 시스템은 미디어 볼륨에 대해 쓰기 작업을 수행하지 않아야 한다 (읽기 전용 마운트에서 동작) | 필수 |

### 3.2 스캔 및 인덱싱 (FR-IDX)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-IDX-001 | 시스템은 기동 시 또는 사용자 요청 시 등록된 모든 루트를 스캔하여 시리즈·권·페이지 목록을 인덱스에 구축해야 한다 | 필수 |
| FR-IDX-002 | ZIP 스캔 시 중앙 디렉터리(central directory)만 읽어 엔트리 목록·오프셋·압축 방식·크기를 인덱스에 저장해야 하며, 엔트리 데이터를 압축 해제하지 않아야 한다 | 필수 |
| FR-IDX-003 | 재스캔 시 파일의 수정 시각과 크기가 변하지 않은 항목은 건너뛰어야 한다 (증분 스캔) | 필수 |
| FR-IDX-004 | 스캔 진행 상황(대상 수, 완료 수, 현재 항목)을 UI에서 실시간 확인할 수 있어야 한다 | 권장 |
| FR-IDX-005 | 인덱스 전체 재구축 명령(`--rebuild-index`)을 제공해야 한다. 인덱스 손실이 데이터 손실로 이어지지 않아야 한다 | 필수 |
| FR-IDX-006 | 다음 항목은 페이지에서 제외해야 한다: `__MACOSX/` 하위, `.DS_Store`, `Thumbs.db`, `desktop.ini`, 숨김 파일, 0바이트 엔트리, 디렉터리 엔트리 | 필수 |
| FR-IDX-007 | 페이지 정렬은 자연 정렬(natural sort)을 적용하여 `1.jpg → 2.jpg → 10.jpg` 순서가 보장되어야 한다. 제로 패딩 유무가 혼재해도 동일하게 동작해야 한다 | 필수 |
| FR-IDX-008 | ZIP 엔트리명이 UTF-8 플래그를 갖지 않는 경우 CP949(EUC-KR)로 재해석하여 한글 파일명이 정상 표시되어야 한다 | 필수 |
| FR-IDX-009 | ZIP64 형식 아카이브를 지원해야 한다 | 필수 |
| FR-IDX-010 | 암호화된 ZIP, 손상된 ZIP은 오류 상태로 표시하되 스캔 전체를 중단시키지 않아야 한다 | 필수 |
| FR-IDX-011 | 지원 이미지 확장자: jpg, jpeg, png, gif, webp, bmp, avif | 필수 |

### 3.3 페이지 서빙 (FR-SRV)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-SRV-001 | **ZIP 내부 이미지는 임시 디렉터리로 압축 해제하지 않고, 아카이브 파일에서 직접 읽어 스트리밍 응답해야 한다** | 필수 |
| FR-SRV-002 | 페이지 요청 시 인덱스에 저장된 오프셋으로 즉시 seek 하여 해당 엔트리만 읽어야 한다 (전체 순회 금지) | 필수 |
| FR-SRV-003 | 압축 방식이 `stored`(무압축)인 엔트리는 압축 해제 과정 없이 바이트 범위를 그대로 전송해야 한다 | 권장 |
| FR-SRV-004 | 자주 접근하는 아카이브의 파일 핸들을 LRU 풀로 재사용하여 반복적인 파일 열기 비용을 제거해야 한다 | 권장 |
| FR-SRV-005 | 폴더 내 이미지 파일은 파일 시스템에서 직접 서빙해야 한다 | 필수 |
| FR-SRV-006 | PDF 페이지는 서버에서 이미지로 래스터화하여 서빙해야 한다. 렌더 해상도는 요청 파라미터로 조절 가능해야 한다 | 필수 |
| FR-SRV-007 | 모든 페이지 응답에 ETag와 `Cache-Control: immutable`을 부여하여 브라우저 재요청을 최소화해야 한다 | 필수 |
| FR-SRV-008 | 원본 이미지는 리사이즈·재인코딩 없이 원본 바이트 그대로 전달함을 원칙으로 한다 | 필수 |

### 3.4 썸네일 및 캐시 (FR-THM)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-THM-001 | 썸네일은 별도의 정식 캐시 디렉터리에 파일로 영구 저장해야 한다 | 필수 |
| FR-THM-002 | 캐시 파일명은 `권 식별자 + 페이지 번호 + 목표 너비`의 해시로 생성하며, 2단계 디렉터리 팬아웃(`ca/che/<hash>.jpg`)을 적용해야 한다 | 필수 |
| FR-THM-003 | 시리즈 커버(첫 권의 첫 페이지)는 스캔 직후 우선 생성해야 한다 | 필수 |
| FR-THM-004 | 권 내부 페이지 썸네일은 최초 요청 시 지연 생성(lazy)한다 | 필수 |
| FR-THM-005 | 썸네일 생성은 백그라운드 워커에서 수행하며 동시 실행 수를 설정으로 제한할 수 있어야 한다 | 필수 |
| FR-THM-006 | 원본 파일의 수정 시각이 변경되면 해당 캐시를 무효화해야 한다 | 필수 |
| FR-THM-007 | 캐시 디렉터리 전체 삭제 시 시스템은 정상 동작해야 하며 자동으로 재생성되어야 한다 | 필수 |
| FR-THM-008 | 캐시 사용량 조회 및 전체 삭제 기능을 UI에서 제공해야 한다 | 권장 |

### 3.5 라이브러리 탐색 (FR-LIB)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-LIB-001 | 시리즈 목록을 커버 그리드 형태로 표시해야 한다 | 필수 |
| FR-LIB-002 | 그리드 뷰와 리스트 뷰를 토글할 수 있어야 하며, 선택 상태는 유지되어야 한다 | 필수 |
| FR-LIB-003 | 리스트 뷰는 시리즈명, 권 수, 총 용량, 수정 일자, 읽기 진행률을 컬럼으로 표시해야 한다 | 필수 |
| FR-LIB-004 | 정렬 기준: 이름(자연 정렬), 수정 일자, 최근 읽은 순, 용량, 권 수 | 필수 |
| FR-LIB-005 | 루트별 필터링이 가능해야 한다 | 필수 |
| FR-LIB-006 | 시리즈명 부분 일치 검색을 제공해야 한다. 한글 초성 검색을 지원한다 | 권장 |
| FR-LIB-007 | 대량 항목에 대해 가상 스크롤 또는 페이지네이션을 적용하여 초기 렌더 성능을 보장해야 한다 | 필수 |
| FR-LIB-008 | 커버 이미지가 없거나 생성 실패한 시리즈는 시리즈명 텍스트가 포함된 대체 표시를 해야 한다 | 필수 |
| FR-LIB-009 | 시리즈 상세 화면에서 해당 시리즈의 권 목록을 표시하고, 각 권의 페이지 수·용량·형식(ZIP/폴더/PDF)·진행률을 확인할 수 있어야 한다 | 필수 |
| FR-LIB-010 | 홈 화면 최상단에 "이어보기" 영역을 두어 진행 중인 권을 우선 노출해야 한다 | 필수 |
| FR-LIB-011 | 커맨드 팔레트(단축키 `Ctrl/Cmd + K`)로 시리즈를 즉시 검색·이동할 수 있어야 한다 | 권장 |

### 3.6 뷰어 (FR-VWR)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-VWR-001 | 전체화면 리더 모드를 제공하며, 페이지 전환은 즉시(체감 지연 없이) 이루어져야 한다 | 필수 |
| FR-VWR-002 | 읽기 방향을 좌→우 / 우→좌(일본 만화) 중 선택할 수 있어야 하며, 권 단위로 설정이 기억되어야 한다 | 필수 |
| FR-VWR-003 | 표시 모드: 단면, 양면(스프레드), 세로 연속 스크롤(웹툰) | 필수 |
| FR-VWR-004 | 양면 모드에서 가로가 긴 페이지(양면 스캔 원본)는 자동으로 단면 처리해야 한다 | 권장 |
| FR-VWR-005 | 맞춤 모드: 너비 맞춤, 높이 맞춤, 원본 크기 (**판정 E-27로 개정 — '화면 맞춤'은 컨트롤에서 제외**) | 필수 |
| FR-VWR-006 | 현재 페이지 기준 다음 3~5페이지를 선행 로드해야 한다 | 필수 |
| FR-VWR-007 | 키보드 단축키를 지원해야 한다: `←/→` 페이지 이동, `Space` 다음, `F` 전체화면, `Esc` 나가기, `T` 썸네일 패널 |  필수 |
| FR-VWR-008 | 페이지 썸네일 스트립 또는 그리드로 임의 페이지에 점프할 수 있어야 한다 | 필수 |
| FR-VWR-009 | 마지막으로 읽은 페이지를 자동 저장하고, 재진입 시 해당 페이지에서 재개해야 한다 | 필수 |
| FR-VWR-010 | 권의 마지막 페이지에서 다음 권으로 연속 이동할 수 있어야 한다 | 필수 |
| FR-VWR-011 | 터치 환경에서 스와이프 및 탭 영역 페이지 이동을 지원해야 한다 | 권장 |
| FR-VWR-012 | 읽기 완료 상태를 자동 판정(마지막 페이지 도달)하고 수동으로도 변경할 수 있어야 한다 | 권장 |

### 3.7 진행률 및 상태 (FR-STT)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-STT-001 | 권 단위 읽기 진행률(현재 페이지 / 전체 페이지)을 저장해야 한다 | 필수 |
| FR-STT-002 | 시리즈 진행률은 소속 권의 완독 수 기준으로 집계·표시해야 한다 | 필수 |

| FR-STT-004 | 진행률 데이터를 JSON으로 내보내기/가져오기 할 수 있어야 한다 | 선택 |

## 4. 비기능 요구사항

### 4.1 성능 (NFR-PRF)

| ID | 요구사항 | 목표치 |
|---|---|---|
| NFR-PRF-001 | 캐시된 페이지 이미지 응답 시작 시간 | 로컬 네트워크 기준 100ms 이내 |
| NFR-PRF-002 | 뷰어 내 페이지 전환 체감 지연 | 프리페치된 페이지 기준 즉시 |
| NFR-PRF-003 | 라이브러리 첫 화면 렌더 (1,000 시리즈 기준) | 1.5초 이내 |

| NFR-PRF-005 | 메모리 사용량 | 유휴 시 200MB 이하 |
| NFR-PRF-006 | 페이지 서빙 시 아카이브 전체를 메모리에 적재하지 않아야 한다 | 필수 준수 |

## 5. UI 요구사항

### 5.1 채택 방향
**라이브러리 그리드형(안 A)을 기본 골격으로 하고, 탐색기형(안 B)의 정보 밀도 높은 리스트 뷰와 리더 우선형(안 C)의 이어보기·커맨드 팔레트를 흡수한 하이브리드 구성.**

선정 근거: 대상 컬렉션은 규모가 크고, 파일명 자체에 권수·완결 여부 등 메타데이터가 담겨 있다. 커버 그리드만으로는 이 정보가 소실되고, 텍스트 리스트만으로는 시각적 식별이 느리다. 두 모드를 대등하게 제공하는 것이 이 컬렉션의 성격에 맞는다.

### 5.2 화면 구성

#### UI-001 홈 / 라이브러리
- 좌측 사이드바(고정): 루트 목록, 이어보기, 최근 추가, 완독, 설정
- 상단 바: 검색 입력, 정렬 선택, 그리드/리스트 토글, 스캔 상태 인디케이터
- 본문 상단: 이어보기 카드 가로 배열 (진행 중인 권이 없으면 영역 숨김)
- 본문: 시리즈 커버 그리드 (반응형 컬럼) 또는 리스트 테이블
- 커버 위 오버레이: 시리즈명, 권 수, 진행률 바

#### UI-002 시리즈 상세
- 헤더: 대표 커버, 시리즈명, 원본 경로, 총 권 수, 총 용량, 전체 진행률
- 액션: 처음부터 읽기 / 이어 읽기 / 이 시리즈 재스캔
- 본문: 권 목록 (썸네일 + 형식 배지 + 페이지 수 + 진행률). 자연 정렬 기본

#### UI-003 뷰어
- 기본 상태: 크롬 없는 전체화면. 마우스 이동 또는 탭 시 상·하단 오버레이 노출
- 상단 오버레이: 뒤로가기, 시리즈명 · 권명, 표시 모드 / 읽기 방향 / 맞춤 모드 컨트롤
- 하단 오버레이: 페이지 슬라이더, `현재/전체` 표시, 썸네일 패널 토글
- 썸네일 패널: 하단 스트립 또는 전체 그리드 오버레이

#### UI-004 설정
- 루트 목록 조회 및 수동 재스캔 실행
- 캐시 사용량 표시 및 삭제
- 기본 읽기 방향, 기본 표시 모드, 테마, 프리페치 페이지 수
- 스캔 로그 열람

### 5.3 UI 원칙
- 시리즈는 항상 시리즈 단위로 표현한다. 파일 시스템 경로는 상세 화면에서만 보조적으로 노출한다
- 로딩 상태는 스켈레톤으로 처리하고 레이아웃 이동(CLS)을 발생시키지 않는다
- 썸네일 미생성 항목도 즉시 자리를 차지하고 준비되는 대로 채워진다

## 6. 기술 제약 및 구현 방침

### 6.1 채택 스택 (솔루션 안 2)

| 계층 | 선택 |
|---|---|
| 백엔드 언어 | Go (1.22 이상) |
| HTTP | 표준 `net/http` + 경량 라우터 |
| 아카이브 | 표준 `archive/zip` (`NewReader(io.ReaderAt, size)` 기반 랜덤 액세스) |
| 인코딩 | `golang.org/x/text/encoding/korean` (CP949 폴백) |
| 인덱스 DB | SQLite — **순수 Go 드라이버**(`modernc.org/sqlite`) 사용 |
| PDF 래스터화 | pdfium 기반. **WASM 런타임(wazero) 모드**를 우선 채택 |
| 이미지 처리 | 순수 Go 이미지 라이브러리. 썸네일 인코딩은 JPEG를 기본으로 한다 |
| 프론트엔드 | React 18 + TypeScript + Vite + Tailwind CSS |
| 자원 내장 | `go:embed`로 Vite 빌드 산출물을 바이너리에 포함 |

### 6.2 핵심 제약

| ID | 제약 |
|---|---|
| CON-001 | **`CGO_ENABLED=0` 빌드를 목표로 한다.** SQLite·PDF·이미지 처리 모두 순수 Go 또는 WASM 경로를 선택하여 정적 단일 바이너리와 손쉬운 크로스 컴파일을 확보한다 |
| CON-002 | PDF 래스터화 성능이 WASM 모드에서 부족할 경우, cgo 빌드 태그를 통한 네이티브 pdfium 경로를 대안으로 두되 기본 배포는 cgo-free를 유지한다 |
| CON-003 | 썸네일 포맷으로 WebP/AVIF를 사용하려면 인코더 의존성이 추가된다. 1차 릴리스는 JPEG로 확정하고 포맷 전환은 캐시 무효화만으로 가능하도록 설계한다 |
| CON-004 | ZIP 아카이브 하나에 대한 동시 읽기는 파일 핸들을 공유하지 않고 `io.ReaderAt` 기반으로 독립 수행한다 |

### 6.3 API 개요

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/roots` | 루트 목록 |
| GET | `/api/series` | 시리즈 목록 (필터·정렬·페이지네이션) |
| GET | `/api/series/{sid}` | 시리즈 상세 및 권 목록 |
| GET | `/api/series/{sid}/cover` | 시리즈 커버 썸네일 |
| GET | `/api/books/{bid}` | 권 메타데이터 및 페이지 목록 |

| PUT | `/api/books/{bid}/progress` | 읽기 진행률 저장 |
| POST | `/api/scan` | 스캔 실행 (전체 또는 특정 루트) |

| GET | `/api/settings` · PUT | 설정 조회·변경 |

## 7. 가정 및 제외 범위

### 7.1 가정
- 미디어 볼륨은 로컬 또는 로컬에 준하는 속도로 마운트되어 있다
- 동시 접속자는 소수이며 쓰기 경합이 사실상 발생하지 않는다
- 컬렉션 규모는 시리즈 수천 개, 총 용량 수 TB 수준이다
- 파일명이 사실상의 메타데이터이며, 외부 메타데이터 소스는 없다

### 7.2 제외 범위 (Out of Scope)
- 외부 메타데이터 서비스 연동 (작가·연재 정보 자동 수집)
- 다중 사용자 계정 및 권한 관리
- 파일 업로드, 이름 변경, 삭제 등 컬렉션 편집 기능
- OPDS 등 외부 리더 프로토콜 서버
- 이미지 자동 보정(업스케일, 컬러 보정)
- RAR/CBR, 7z 지원 — 단, 아카이브 리더는 인터페이스로 추상화하여 후속 확장 여지를 남긴다
